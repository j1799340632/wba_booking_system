# 第 9 轮：评估计划跟进

修改保留在本地 `feat/booking-assistant-local`，未提交或推送 GitHub；仅更新隔离演示环境，保留已有预约与个人目标。

## 解决的问题

个人评估规划原先只有各类型的完成、预约和缺口数量，无法直接找到需要跟进的具体记录。现在 Assessment Plan 的 **Your next actions** 展示真实本人预约，并提供 **View booking** 定位到 My Bookings 的对应记录。Dashboard 的目标区同步显示截止日期、待检查状态和待审批数量。

查询、展开、跳转和刷新均只读。清单不会自动审批、完成、取消预约，也不会向导师或学生发送新提醒。原项目已有的提醒机制不在本轮改动范围内。

## 规则与交互

只读取当前学生未删除的 Pending 或 Confirmed 记录；评估类型必须属于已保存目标，实际预约起止时间必须完整落在计划期间内。未配置目标时先显示目标表单。已完成、取消、拒绝、其他学生、无关类型或周期外的预约不进入清单。

| 清单分类 | 判断与建议 |
| --- | --- |
| Scheduled start passed — approval missing | Pending 且已到开始时间；向导师核实状态，不视为已获批准或已完成 |
| Scheduled end passed — check completion | Confirmed 且已到结束时间；核实完成情况，不能由时间经过自动判定完成或缺席 |
| Session in progress | Confirmed 且开始时间 ≤ 当前时间 < 结束时间 |
| Confirmed — starts within 48 hours | 未来已确认场次，距开始最多 48 个实际小时，包含恰好 48 小时 |
| Awaiting supervisor approval | 开始时间仍在未来的 Pending |
| Confirmed — scheduled later | 超过未来 48 小时的已确认场次 |

按表中顺序、实际预约开始时间排序。后端返回前 20 条，汇总数量按全部匹配记录计算；页面默认展开 4 条，可展开至已返回的 20 条，更多记录明确引导至 My Bookings。这里使用预约的实际场次时间，不使用重复时段模板日期。

页面显示本次查询时间与 `Australia/Sydney`。状态和时间不会在页面停留时自行刷新，需点击 **Refresh** 或重新进入页面。未来 48 小时按实际经过时间计算，跨 Sydney 夏令时仍保持 48 小时；截止日期按 Sydney 日历日计算，当天仍有效，剩余未完成且距截止日不超过 7 个日历日时突出提示。这是个人计划提示，不代表课程规定、导师审批时限或完成保证。

截止提示同时显示仍待完成数量与还需提交的预约数量，可跳转至真实场次推荐；截止日已过则提示检查日期和目标。目标已完成时仍保留未解决的额外预约，避免隐藏真实记录。

My Bookings 会突出并聚焦跳转的本人记录。URL 中的预约编号只用于定位已经按本人权限查询的列表，不作为跨学生查询条件。记录已不可用时给出返回计划刷新的提示。预约模板归档后仍能读取相关记录；导师已删除或历史时长缺失时显示明确的缺失信息。

## 统计一致性

过去仅按开始时间判断“过期”，会把正在进行的评估误计为已错过。本轮改为只有结束时间已过才计入原 `missed` 统计，页面称其为“已结束但未完成”，不推断是否实际出席。

进行中的 Confirmed 单独计入 `inProgress`，可提供临时覆盖，避免此时重复推荐补约；进行中仍未获批的 Pending 不提供覆盖，进入状态检查清单。计算为：

```text
剩余完成数 = max(目标 - 周期内实际完成数, 0)
还需提交的预约数 = max(剩余完成数 - 未来已确认 - 未来待审批 - 进行中已确认, 0)
```

已完成数量仍只来自 Completed 状态和有效的完成日期。无效或缺少实际起止时间的未完成记录不进入清单、临时覆盖或每周统计，保留无法可靠统计的记录提示。保存目标、读取清单和查看预约均不修改完成进度。

## 实现与验证

复用 `GET /student/assessmentPlan` 的完整与 summary 响应，增加查询时间、截止日距离、进行中数量、待办列表和完整分类汇总。继续在服务端校验学生角色、账号状态与数据所属者；不接受模型提供的预约编号或状态。

没有数据库迁移、模型协议或提示词变更，也没有额外模型调用。沿用既有模型解析评测记录，本轮验证不能解释为新的模型准确率或生产可靠性结论。

- Maven package、108 项后端测试通过；新增 7 项真实 SQL 服务测试，覆盖所属者、类型和周期过滤、排序与截断、进行中覆盖、归档及缺失数据、状态变化、截止日期，以及 Sydney 春季夏令时的 48 小时边界。
- 前端 22 项测试通过；新增 3 项检查截止日文案、长编号精确跳转和不同状态的提示。修改的计划、待办、My Bookings、Dashboard 与辅助函数通过 ESLint，Vite 构建通过。原有 bundle 体积提示仍存在。
- 真实 Edge、Spring、MySQL、Redis 链路验证 5 组场景：六类动作和正确统计；归档模板预约精确跳转且不写入；审批、完成与取消后重新加载和刷新；跨学生编号与角色隔离；截止日已过的提示与周期过滤。
- 浏览器使用 Los Angeles 时区，页面保持 Sydney 的实际预约时间；1440px 桌面和 390px 手机宽度无横向溢出，无页面脚本错误。
- 对比已有预约及目标快照，只使用碰撞检查通过的专用账号、时段与记录，验证后清理这些测试数据。读取和导航未新增消息或改变预约、目标、完成日期。
