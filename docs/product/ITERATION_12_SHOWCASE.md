# 第 12 轮：可复现演示与作品集表达

全部修改保留本地，没有提交、推送或重新部署原 Docker 项目。

## 本轮解决的问题

之前的自动验收会清理专用账号和场次，默认 seed 的日期也会过期，因此“测试通过”不等于“随时可以让人手动演示”。本轮补充持久演示数据、动态日期的五分钟演示稿，以及有证据边界的 AI 产品经理案例稿。

新增 `scripts/demo_showcase.py setup/status/cleanup`。首次在独立 `wba-ai-demo` 中创建三种角色、六个场次、两条历史合成预约与个人目标；未来主场次按 Sydney 当前日期加七天生成。重复 setup 保留已产生的预约、审批、结果和观察，只有明确 cleanup 后再 setup 才创建新一轮。

历史合成数据包含一条已完成记录、一条已结束但尚未完成的 Confirmed 记录。现场审批的是刚创建的未来预约，现场录入结果的是历史合成预约，避免提前完成未来评估。个人示例目标为 Mini-CEX 3 次、DOP 2 次，不作为课程配额。

## 清理边界

连接方式固定为隔离 demo 的 Compose MySQL 服务，不读取原部署数据库地址或模型密钥。脚本不调用模型、不发外部邮件，不插入虚构观察事件。

资源清单位于忽略目录 `.local/wba-demo/showcase/manifest.json`，先记录 prepared，再用一次 SQL 事务创建全部数据；提交后更新为 ready。已提交但尚未写回 ready 的完整数据可以由重复 setup 恢复。操作使用 OS 文件锁，进程退出后自动释放。

清理必须同时匹配清单、固定用户身份和该轮场次标记，锁定相关记录后在事务内再次校验归属。其他学生占用专用场次、演示账号操作非专用场次、存在其他账号/字典/日历关系或身份标记变更时，会拒绝清理并保留清单，不自动接管或扩大删除范围。原有账号、预约和个人目标不会被重置。

需要开始新一轮时，先退出专用账号并停止其进行中的请求，再执行 cleanup → setup。cleanup 会删除专用账号的演示观察；若需保留聚合摘要，先从看板下载。看板汇总隔离 demo 全部学生，不能把所有计数当成本轮演示独有结果。

## 实际验证

最终一次 `verify_showcase.cjs --live` 执行完成，五组验证通过，无浏览器脚本错误：

1. 首次创建与重复执行：三用户、六场次、两预约、一目标，重复执行保持相同归属清单和数据；没有模型调用或假观察。
2. 清理保护：缺失清单时不接管已占用 ID；标记不同或其他学生预约专用场次时整批拒绝。额外在预检查后注入标记变化，确认事务内检查也会阻止全部删除。
3. 使用动态演示稿中的真实查询，调用一次当前配置的 DeepSeek，学生页面从真实候选预览、勾选并确认，只新增一条 Pending；此后 setup 保留新记录。
4. 导师批准未来预约后完成数仍为 1；导师完成昨天的历史合成记录，学生点击 Refresh 后完成数从 1/5 变为 2/5、剩余由 4 变为 3，未来 Confirmed 保持临时覆盖。学生与导师浏览器分别使用 Shanghai 和 Los Angeles 时区。
5. 管理员页面读取真实运行统计；搜索、预览、确认形成三条观察，模型调用仅一次。关闭账号页面后完整清理，核对其他预约、目标和既有观察不变，再创建全新演示供用户使用。

最终一次验证只发起一次真实模型请求，开发过程的重跑另计。该验证是合成数据验收，不是生产准确率或用户收益研究。后端和前端产品代码未在本轮改变，因此没有为文档/脚本更新重跑之前的 147/29 项业务测试；本轮执行 Python 编译检查、Node 语法检查、Markdown 本地链接检查、真实数据库及多角色浏览器验证，并查看截图。

冻结验收摘要见 [本轮合成验证记录](../../evals/results/)（`*-showcase-workflow.json`）。完整报告与截图位于忽略目录 `.local/wba-demo/browser/showcase-*`，截图属于验证时使用并已清理的上一轮合成账号；当前动态稿对应验证结束后新建的一轮。
