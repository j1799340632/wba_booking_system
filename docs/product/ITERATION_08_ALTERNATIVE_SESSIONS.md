# 第 8 轮：无结果时的替代场次

所有修改继续保留在本地 `feat/booking-assistant-local`，未提交或推送 GitHub。仅更新隔离演示环境，保留用户已有预约与个人评估目标。

## 交互与边界

Book Slots 的 AI 助手先按全部原条件查询，并检查真实可约性。有匹配时继续返回 READY 与原候选；没有时保持 NO_RESULTS、原条件与空的主候选列表，再单独展示 **Alternatives — one condition changes**。

候选变化按以下顺序尝试，每组只改变一个条件维度：

| 变化 | 保留 |
| --- | --- |
| 整个查询时间窗延后一周 | 相同本地起止时刻、每日时间限制、星期限制、导师 |
| 原日历日期内改选其他时间 | 原日期、星期、导师；清除每日时间限制并扩展到这些日期的全天 |
| 换另一位导师 | 原日期、每日时间和星期限制 |
| 同一日期窗内其他星期 | 原日期边界、每日时间、导师 |

评估类型、医院和科室筛选始终保留；原先未指定的筛选继续不限定。软导师偏好继续排序，不会变成硬条件。短时间窗可以提出改选当天其他时间；默认 30 天查询不会被误当成用户设置的每日时间限制。

每组最多 2 个候选，最多展示 3 组，跨组去重。没有真实候选的变化不展示。候选来自原有时段查询和统一预约校验，过滤禁用或过期时段、失效账号、非真实重复场次，以及学生或导师已有的重叠预约。普通精确查询也增加了同样的可约检查。

这些是有限窗口内的例子，没有检查全部可能组合，也不会声称查不到的原因一定是导师没空。如果替代查询暂时失败，保留原条件的无结果状态，并说明建议加载失败；不会生成虚构场次。

用户选择 **Review alternative** 或 **Review alternative reschedule** 后，预览再次展示原条件与变化。需要勾选接受变化并确认，才沿用既有服务端预览与幂等确认接口提交。关闭预览不写入预约。改期继续在同一事务内取消原预约、创建 Pending 替代请求；替代失败保留原预约。

确认成功后移除对应替代候选；中断响应后重试仍返回同一预约。后续可约性变化由预览、确认及重新查询再次检查。

## 实现

`BookingSearchAlternatives` 构建独立的条件副本，原查询及星期列表不被修改。日期平移使用业务本地日期与时刻，跨 Sydney 夏令时仍保留同一墙上时间。时间变化正确处理结束日期的排他午夜，避免多扩展一天。

`BookingAssistantService` 的精确查询与替代查询使用统一候选收集和可约检查。改期查询只排除所选本人原预约的冲突，仍检查其余占用，并拒绝把原场次作为替代。空的预约管理列表、需要澄清的条件和评估规划不会触发新预约建议。

`BookingAssistantResult` 增加 `alternatives`，包含变化类型、说明、替代条件和真实候选。前端显示前后条件，保持原条件回显；替代候选不会放进“完全匹配”列表。

本轮没有数据库迁移，也没有修改模型提示词或结构化解析协议。模型仍只解析原条件；替代条件与候选由后端规则和真实数据库生成，不额外调用模型生成推荐。

## 验证

- Maven package 与 101 项后端测试通过。在原有 91 项基础上新增 4 项变化规则测试、4 项助手服务测试、2 项真实 SQL 查询测试。
- 前端 19 项测试通过；新增条件变化说明、长 ID 保留、原状态保留、移除已预约候选、错误结构处理及每日开放时间边界测试。
- AI 组件与辅助函数 ESLint、Vite 构建通过；原有 bundle 体积提示仍存在。
- 真实 Edge、DeepSeek、Spring、MySQL、Redis 链路：原查询无结果时分组展示真实日期、时间和导师替代；禁用、不同类型或不同医院时段不混入。
- 核对关闭与明确接受变化、丢失响应后重试只产生一条 Pending 预约与两条通知、从替代建议完成原子改期。
- 预览后另一个学生占用同导师的不同模板时，确认被拦截，重新查询移除建议；已保存的其他预约不变。
- 真正完全匹配仍返回 READY，不生成替代组，也不写预约。
- 桌面与 390px 手机宽度检查、页面脚本无错误。仅清理碰撞检查通过的专用账号及其预约、通知、时段，并对比已有预约和目标快照。
