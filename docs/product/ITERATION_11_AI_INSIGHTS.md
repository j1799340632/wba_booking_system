修改仅在本地 `feat/booking-assistant-local`，未提交或推送 GitHub，未修改原部署。

## 目标与入口

已有固定意图评测与真实预约闭环，但缺少使用过程中可以核对的请求、确认、延迟和模型用量汇总。本轮新增管理员和超级管理员菜单 **AI Insights**，支持选择 1–31 个日历日，查看每天活动、全部操作结果、确认保存与重试、P50/P95 耗时和模型报告的 Token，并下载同一聚合 JSON 摘要。

隔离演示账号：`admin@wba.test` / `WbaDemo!2026`。地址：`http://127.0.0.1:5178/home/admin/assistant-insights`；超级管理员使用对应 `/home/super-admin/assistant-insights` 路由。

数据从本轮记录机制启用后开始采集，没有从旧日志补造历史。没有数据时显示明确空状态，耗时和未报告的用量显示未知。测试数据验证后会清理；可以先用学生账号发起一次助手请求，再登录管理员查看。

## 统计口径

| 观察阶段 | 记录内容 |
| --- | --- |
| SEARCH | `/search` 的 READY、CLARIFY、NO_RESULTS、BOOKINGS、PLAN、UNAVAILABLE、UNSUPPORTED 等结果；包括查预约和规划意图，不只是查场次 |
| REPLACEMENTS | 不调用模型的真实改期候选查询结果 |
| PREPARE_BOOKING | 预约预览成功、规则拒绝或异常 |
| CONFIRM_BOOKING | 首次保存 SAVED、已保存结果重放 REPLAYED、规则拒绝 REJECTED、意外异常 ERROR |
| PREPARE_MANAGEMENT | 取消或改期预览，保留动作类型 |
| CONFIRM_MANAGEMENT | 取消或改期保存、重放、拒绝或异常，保留动作类型 |

“新预约保存数”只统计 CONFIRM_BOOKING 的 SAVED，代表当时保存的 Pending 请求。不是已获导师批准或已完成的评估数量，之后取消也不改写当时的保存次数。改期和取消在 Change confirmations 中按动作分别显示。

“确认保存率”是 `(SAVED + REPLAYED) / 全部 CONFIRM_BOOKING 尝试`，衡量确认请求是否得到已保存回执。重试返回已有预约属于成功尝试，但不会增加新保存数。没有确认尝试时不显示虚构的 0% 或 100%。

这些是各阶段的操作次数，**不是关联到同一会话的搜索→预约转化漏斗**。规划页推荐也复用预约预览和确认接口；不能直接把保存数除以搜索数来宣称 AI 转化率。请求进入观察机制之前的认证、绑定、参数验证等失败不属于该完整观察范围。

READY 仅代表返回了真实候选，不证明意图提取正确。固定用例评测与人工复核衡量识别质量，运行看板衡量实际操作结果，二者分开。没有在本轮重新宣称生产准确率或重跑旧 80 条模型评测。

## 时间、用量与未知值

日期边界使用业务时区 `Australia/Sydney`，查询期间包含结束日期全天；查询今天时只计算到当前服务端时间。界面不使用浏览器本地日期计算默认范围或快捷日期，因此位于其他时区也显示同一报告范围。日趋势会补齐没有事件的日期。

Search P50/P95 针对全部 SEARCH 操作的服务端处理时间，包括等待模型、正常结果和失败结果；不包含浏览器、浏览器到服务器的传输、指标写入及返回序列化耗时。使用 nearest rank：`rank = ceil(p × N)`，按耗时、事件编号排序后读取对应实际值；无请求时没有百分位。P50 不是偶数样本的两项平均值。

模型调用数在实际尝试发送请求时增加；只有模型完整报告非负整数的 input、output、total Token 时计入已报告用量。未知用量不会估算为零。即使模型内容解析失败，已收到的有效 usage 仍可统计。前端显示“已报告 Token”和报告覆盖的调用数，不推算金额。

调用记录使用一次操作的独立上下文，同线程上的后续预览、确认或其他用户请求不会继承上一次模型用量。现有离线评测的 `lastUsage()` 保持独立，模型提示词与业务意图协议没有改变。

## 数据与业务边界

新表 `assistant_event` 仅保存阶段、结果、允许的动作枚举、耗时、替代组数量、配置模型名称、用量数字与服务端时间。事件内部保留学生账号 ID，供数据管理和测试隔离使用；管理员 API 不返回账号 ID、预约 ID、逐条事件或可识别的学生/导师信息。不会保存聊天正文、筛选条件、场次详情、评分反馈、provider body、密钥或 endpoint。

API 仅允许当前有效且角色一致的 Admin/SuAdmin 读取聚合数据；学生、导师、禁用账号和已变更角色的旧身份均被拦截。报告下载只包含当前 API 的聚合响应。

观察记录在独立事务中尽力写入，失败不能回滚已保存的预约、替换业务回执或改变原异常。丢失事件数在当前进程内累计，页面提示报告可能不完整；该计数重启后清零，不是持久化丢失率。预约和管理服务的业务回执仍是判断是否已保存的依据。

聚合查询在一致的只读事务中计算结果，耗时分位数从排序后的数据库查询获取，不将全部原始事件载入前端。当前查询最多 31 天，未新增自动保留期删除任务。

## 本地部署变化

`scripts/demo/migrate_assistant_events.sql` 使用 CREATE TABLE IF NOT EXISTS 增量建表，不重置预约或目标。完整初始化 schema 同步包含该表；本轮只在隔离 demo 中实际执行迁移。

`ensure_insights_admin.sql` 只在独立 demo 中创建公开模拟管理员；ID 或邮箱已存在时不覆盖已有账号，也不会向原部署插入该账号。

## 验证与实际结果

- Maven package、147 项后端测试通过。本轮新增 8 项聚合与事务测试、2 项 provider usage 测试、7 项真实 AOP 调用测试和 2 项接口权限测试。
- 验证日期和当前时刻边界、31 天限制、nearest-rank 分位数、空数据、未知与已报告零用量、分阶段计数、结果重放、同线程连续请求的用量隔离、账号权限，以及指标事务失败不回滚业务写入。
- 前端 29 项测试通过，新增 4 项覆盖长整数精度、重试成功率、非法日期与跨月/夏令时日期快捷范围。页面、辅助函数和 API 通过 ESLint，Vite 构建通过。路由配置原本按常量导出数组，与 react-refresh 规则冲突；仅在该配置文件的检查命令中关闭这一个既有规则，其余检查通过，没有全仓 lint 通过的宣称。原有 bundle 体积提示仍存在。
- 最终真实 Edge + DeepSeek + Spring + MySQL + Redis 验证 5 组场景。一次完整执行发起 2 次真实模型请求；开发过程中有多次重跑，最终报告只代表其对应的一次执行。
- 最终执行得到 READY 和 CLARIFY 各 1 次，另有预览、首次预约保存、重试回执、越权确认拒绝、改期候选、取消预览、取消保存及重试，共 10 条操作观察。预约只创建 1 条；只有 2 个搜索操作调用模型。
- 为检查历史日期筛选，仅将专用测试账号的观察时间移动到前一天；业务预约时间未改动。历史报告准确显示 1 次新保存、1 次重放、1 次拒绝，确认尝试保存率 66.7%。这是刻意包含失败的合成场景，不是线上成功率或识别准确率。
- 最终这 2 次模型调用都报告 usage，共 5,405 Token：5,276 input、129 output。观测到的请求 P50 为 813 ms，P95 为 1,388 ms；仅供这两个合成请求的运行记录核对。
- 管理员与超级管理员可读取，学生和导师不能；越权调用助手不记为学生使用。无对话、姓名、预约编号、成绩或凭据出现在聚合响应中。
- 浏览器处于 Los Angeles 时区，仍使用 Sydney 报告日期；1440px 桌面及 390px 手机宽度无横向溢出，无页面脚本错误。下载摘要与页面所用聚合响应一致；网络失败时保留上次报告，恢复后可重新加载。
- 验证后清理碰撞检查通过的专用账号、时段、预约、通知与观察记录；原有预约和个人目标保留，不留下虚构运行量。
