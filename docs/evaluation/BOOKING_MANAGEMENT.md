本轮相关 ESLint 不代表全仓 lint 通过；Book Slots 旧有的 effect 内 setState 报告仍属于已记录的既有问题。

浏览器验证使用 Edge、真实 DeepSeek、Spring 后端及独立 MySQL / Redis：

1. 自然语言查看本人预约；其他学生的记录不出现。预览、关闭、未勾选、`confirmed:false` 均不变更数据；其他学生不能确认此预览。
2. 从完整中文改期指令分别提取原日期和目标日期；查看原、新预约后确认。在服务端已提交后刻意丢弃 HTTP 响应，原弹窗重试获得相同新预约 ID，原记录 Cancelled、新记录 Pending，通知无重复。
3. 自然语言取消新预约，单独核对并确认；My Bookings 保留 Cancelled 记录。
4. 删除指定测试 Redis 预览模拟过期、修改地点模拟详情变化，都不能执行旧预览；预览后由另一学生抢占目标时段，改期失败，原预约状态和占用保持有效。
5. 三个并发确认只取消一次；普通取消接口重复调用不重复生成消息；导师角色不能进入学生管理入口。
6. 取消后原场次可重新预约。新预约仍需搜索、预览、勾选确认，结果为 Pending，未被管理功能改变。

`scripts/demo/verify_booking_management.cjs --live` 在开始时检查专用 ID 无碰撞，结束后只清理本次创建的账号及其预约、消息和时段。清理后比较既有预约 ID、归属、时段、状态、删除标记和版本，验证此前手动测试数据保持不变。完整浏览器记录及截图保存于忽略目录 `.local/wba-demo/browser/`。

## 真实模型评测

所有样本为开发者编写的合成请求，使用固定参考日期与合成字典，通过实际 `JsonBookingIntentParser` 调用配置的 `deepseek-flash`。评测检查白名单、动作、必要条件、原日期和目标日期是否混淆，以及哪些合成场次应被日期条件包含或排除。评测不写预约数据库。

管理集与原有主集、补充表达分别使用各自配置的固定参考时间。主集的取消、改期两条期望随新能力更新，其余样本保持不变。早期历史报告未覆盖或重算。

| 阶段 / 集合 | 通过数 | 发现与调整 |
| --- | --- | --- |
| 管理集初版 | 18 / 20 | 详细“查看”请求误成 SEARCH；目标日期被复制为原日期 |
| 管理规则补充后 | 19 / 20 | 一条 Pending 查询输出不符合严格 schema，适配器拒绝 |
| 状态字段示例补充后 | 20 / 20 | 管理集通过 |
| 原主集首次回归 | 39 / 40 | 搜索追问“改成周四”误成已有预约改期 |
| 搜索上下文规则补充后 | 40 / 40 | 主集通过；随后补充表达中 9 / 10，一条两日范围多包含一天 |
| 日期边界规则补充后的最终管理集 | **20 / 20** | 最终版本 |
| 最终主回归集 | **40 / 40** | 最终版本 |
| 最终补充表达集 | **10 / 10** | 最终版本 |

最终版本每条样本各运行一次：

| 集合 | 中位耗时 | P95 | 总 Token |
| --- | --- | --- | --- |
| 管理 20 条 | 745 ms | 1,122 ms | 32,670 |
| 主回归 40 条 | 796 ms | 1,147 ms | 65,768 |
| 补充表达 10 条 | 967 ms | 1,267 ms | 16,532 |

最终三组共 114,970 Token。本轮各次意图评测累计 240 条真实模型调用，浏览器调用另计。逐条结果保存在 [结果目录](../../evals/results/)中对应管理、主回归和补充表达的报告；早期版本的中间输出也保留在忽略目录 `.local/wba-demo/management-*.json`。

这些结果只能说明当前样本与单次运行通过，不能当成线上准确率、稳定性或用户满意度。补充表达已经用于发现问题并调整规则，最终结果属于回归验证，不再作为独立盲测。模型可能误解或返回不符合格式的结果；服务端会拒绝无效结果，用户仍需查看真实记录、核对详情并明确确认。

没有真实用户行为实验，也未验证邮件或 Google Calendar 的外部同步。导师最终审批仍走原有业务流程，改期请求不会自动获得批准。
